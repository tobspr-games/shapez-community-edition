# 08. 대형 공장 성능, C++ / WebAssembly 계획

## 현상과 우선순위

- 사용자는 Shapez 1에서 공장 확장 후 FPS 및 시뮬레이션 반응 저하를 경험했다.
- 게임 틱 빈도를 180에서 60으로 낮추었을 때 체감 성능이 크게 좋아졌다고 보고했다.
- 따라서 **모니터 주사율과 게임 시뮬레이션 TPS를 구분하고**, 틱당 계산 비용과 렌더 비용을 따로 계측한다.
- 제공된 대형 세이브에는 114,030개 엔티티와 110,038개의 벨트 경로 내부 도형이 있어 실제 벤치마크 데이터로 활용 가능하다.

## 기술 목표

- 현재 게임과 동일한 도형 처리 규칙을 유지하면서 동일 하드웨어에서 평균/상위 분위 틱 처리 시간을 줄인다.
- FPS, 평균 TPS, 95/99 percentile 틱 시간, GC 할당량, 메모리, 엔티티·벨트 수를 기록.
- 실제 생산량과 아이템 수 보존도 함께 검증한다. **속도만 빠르고 도형이 사라지는 최적화는 실패.**

## 단계별 접근

### Phase A: 측정부터

1. 시스템별 시간 계측: 벨트 이동, 프로세서, 아이템 입출력, 렌더/청크 드로우, 회로, 미래의 전력/텔레포터.
2. 고정 시드/고정 저장 세이브 복사본에서 워밍업 후 여러 번 측정.
3. 화면을 멀리/가까이 했을 때 변화로 렌더 병목과 시뮬레이션 병목 구분.
4. 테스트 중 `speed-control` 모드의 시간 배율 변형에 따른 영향 통제.

### Phase B: JS/TS에서 낮은 위험의 최적화

- 아이템 경로 처리에서 불필요한 객체 생성/반복 조회 제거.
- 활동 중인 장치만 갱신하거나 dirty flags 도입(정확성 확인 필요).
- 채널 기반 텔레포터 레지스트리 구축 (기존 전수 조회 제거).
- 검색 작업을 여러 프레임으로 나눔.
- 전력망의 연결성은 설치/해체/스위치 변경 시에만 재계산하고, 매 틱 공급·수요만 평가.
- 벨트 렌더 캐싱/가시 영역 제한은 GPU/Canvas 측정에서 병목 확인 시 수행.

### Phase C: 벨트 경로/대량 운송 데이터 구조 설계

- 개별 도형 객체 대신 연속 메모리 구조(SoA 등)를 실험한다.
- 같은 도형 N개를 `Packet(shapeId, count)`로 처리하는 물류는 구조적으로 별개이며, 선택 가능한 새 설비로 적용한다.
- 수량·순서·간격·충돌 규칙을 정확히 유지하는 테스트가 먼저.

### Phase D: C++20 + Emscripten/Wasm 프로토타입

- 가장 큰 병목이 확인된 **하나의 모듈**(예: 벨트 처리)을 독립 벤치마크로 이식한다.
- JS와 Wasm을 각자 동일한 입력으로 N틱 실행해, 결과 데이터와 처리 시간을 비교한다.
- 상태는 가능한 한 Wasm 메모리에 유지하고, 프레임마다 수많은 JS 객체를 교환하지 않는다.
- Rust 또는 C++ 등 다른 네이티브 언어로 급변경하지 않는다. 사용자 선호는 C++이지만 실제 성능 이득 검증 후 결정.

## 벤치마크 예시 (초기 실험안)

- 10,000 벨트 타일, 50,000 아이템, 10,000틱 실행; 60TPS에 해당하는 로직 규칙.
- 평균/최대 지연, p95/p99, 아이템 보존, 결과 해시, 메모리 사용량.
- 소형/중형/실제 대형 세이브로 모두 테스트한다.
- Wasm과 JS 사이 호출/복사 비용을 포함한 **전체 게임 관점 성능**을 비교한다.

## 예상되지 않은 최적화 함정

- 컴파일 언어 전환만으로 렌더 FPS가 향상되는 것은 아니다.
- 엔진 본체에서 시간을 거의 쓰지 않는 부분을 10배 빠르게 해도 전체 개선폭은 작다(암달의 법칙).
- 벨트 속도 ×2는 아이템 속도만 변경하지 않고 **일반 벨트 ↔ 고속 벨트 간 경계의 정체 및 간격**도 정확히 처리해야 한다.
- 전력망이나 텔레포터를 매 틱 전 맵 순회로 구현하면 새 기능 자체가 새로운 병목이 될 수 있다.
- UI/모드 API와 엔진의 연결을 성급하게 끊으면 기존 모드 기능을 다시 구현하기 어려워진다.

## 승인 기준

네이티브 엔진 도입의 근거는 "C++가 빠를 것 같다"가 아니라 **실측된 전체 틱 시간 감소**, **동일한 게임 상태 및 생산량**, **세이브/모드 API 유지 가능성**이어야 한다.
