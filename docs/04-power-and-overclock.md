# 04. 지정 도형 연료 발전·전력망·오버클럭

## 확정 게임플레이 요구사항

1. **[확정] 도형의 복잡도를 자동 산정해 발전량을 주는 방식은 사용하지 않는다.** 동일 도형을 4층으로 쌓아 점수를 얻는 편법을 피하기 위해, 발전기마다 **미리 정의된 정확한 연료 도형 코드**를 요구한다.
2. **[확정] 발전기 티어는 6개.** 각 티어에서 동시에 필요한 서로 다른 도형 종류 수는 `T1=1 / T2=1 / T3=2 / T4=3 / T5=4 / T6=6`.
3. **[확정] 티어가 올라갈수록 요구 도형의 제조 난이도와 발전량이 증가**한다.
4. **[확정] T6는 준무한에 가까운 출력을 제공**한다. 최종 자동화 성취 보상에 가까운 설계.
5. **[확정] 전력으로 기존 가공 건물·벨트 등을 2배 오버클럭**할 수 있다. 상당한 추가 소비 전력을 요구하며 초중반에는 사실상 어렵게 한다.
6. **[합의된 방향] Mindustry처럼 주변 건물에 전력을 범위 공급하는 배전탑**을 도입한다.
7. **[합의된 방향] 기존의 논리 전선/회로와 신규 전력망은 별개**, 회로로 발전소·오버클럭·우선순위를 제어할 수 있다.
8. **[합의된 방향] 기존 기본 생산 건물은 무전력으로 일반 속도 동작**한다. 연료 공장의 정전 영구 고착을 막는다.

## 연료 사이클과 안전성

- 한 사이클에 요구된 `N`종의 연료가 **모두 존재**할 때만 원자적으로 `N`개(또는 티어 정의 수량)를 소비한다.
- 일부만 도착하면 기다리며, 연료 유실/부분 소비 금지.
- 각 연료 종류별 입력 버퍼와 상태 표시를 제공한다.
- T6는 6종 독립 입력을 실용적으로 처리할 수 있는 크기/포트 구조가 필요하다.
- 기존 티어 연료 도형을 상위 티어에서 일부 재사용하는 것은 [제안]이며 고유 도형 17종을 강제하는 것은 아니다.
- **T6 해금 연구:** [제안] 최고급 6종을 안정적으로 자동 생산·납품하도록 요구. 정확한 수량 미정.

## 초기 밸런스 표 — 전부 [제안], 확정 값 아님

| 티어 | 동시 연료 종류 수 [확정] | 예시 발전량(PU/s) | 예시 사이클 | 대략 난이도 |
| --- | ---: | ---: | --- | --- |
| T1 | 1 | 50 | 10초 | 단순 1층 |
| T2 | 1 | 200 | 8초 | 복합 1층 |
| T3 | 2 | 900 | 6초 | 2층 |
| T4 | 3 | 4,500 | 5초 | 2~3층 |
| T5 | 4 | 25,000 | 4초 | 3~4층 |
| T6 | 6 | 100,000,000 | 2초 | 최고난도 4층 |

- `PU`는 신규 가상 전력 단위이다. **발전량, 사이클, 실제 6티어 연료 코드, 건물 크기, 연료 버퍼는 아직 확정되지 않았다.**
- T6는 실제 무한대 `Infinity`가 아닌 충분히 큰 *유한 값*으로 계산하는 방향을 제안한다.
- T6 출력을 계산할 때 실제 사용 전력 이상의 불필요한 정밀 연산을 피할 수 있다.
- 발전 효율은 연료 1개 기준만이 아니라 **연료 공급 공장의 순전력 생산량** 관점에서 조절한다.

## 전력망 모델

```text
정해진 도형 연료 공장 -> 발전기 -> 연결 전력망 -> 배전탑 -> 고급 설비 및 오버클럭
                                                   -> 축전지
                    논리 회로 ------------------------^ (제어)
```

- 배전탑은 전력을 *생성하지 않고*, 동일 네트워크의 발전량을 범위 내 건물에 제공한다.
- 범위가 겹쳐도 건물의 소비 전력을 중복 계산하지 않는다.
- 설치/철거/배선 변경 시 네트워크 위상을 갱신하고, 매 틱에는 활성 네트워크의 수요·공급·저장량을 집계하는 **dirty-graph 캐시** 방향을 제안한다.
- 축전지의 충전/방전 제한과 전력 우선순위를 별도 설계한다.
- 회로가 제어하는 전력 스위치가 있으면 상태 변경 시 네트워크 위상을 다시 계산한다.
- 현실적인 전압/저항/송전 손실은 초기 범위에 없다.

## 오버클럭 규칙

- 최종 속도는 기본 업그레이드 속도에 `×2`를 적용한다. **게임 전체 TPS를 두 배로 올리지 않는다.**
- 대상: 채굴기, 벨트, 절단/회전/적층/색칠 장비, 일부 분배/물류 건물(세부 범위 미정).
- 발전기는 오버클럭 제외를 권장한다. 텔레포터는 별도의 처리량 업그레이드가 더 적합할 수 있다.
- 범위 배전탑이 중첩돼도 오버클럭 속도는 최대 `×2`.
- 전력 부족 시 기존 무전력 설비는 1배로 복귀한다. 확장판 고급 설비는 독자적 전력 부족 규칙이 필요하다.
- 오버클럭은 플레이어/회로가 의도적으로 켜야 하며, 전력 잔량에 따라 매 틱 토글되는 현상을 막는 히스테리시스/최소 유지 시간이 필요하다.

### 오버클럭 전력 가격 — [제안] 전부 테스트 전

| 대상 | 추가 소비 예시 |
| --- | ---: |
| 오버클럭 배전탑 | 200 PU/s |
| 벨트 1타일 | 30 PU/s |
| 채굴기 | 300 PU/s |
| 일반 가공기 | 400 PU/s |
| 고급 가공기 | 600 PU/s |

예시: 배전탑 + 벨트 70타일 + 일반 가공기 5개 = `200 + 70×30 + 5×400 = 4,300 PU/s`. **밸런스 검증 전 수치**로만 취급한다.

## 상태 및 정합성 테스트

- 연료 N종 중 1종만 부족: 발전 사이클 전체가 대기하고 이미 확보한 연료는 유지.
- 연료 소진/축전지 방전/회로 차단: 상태 전이 중 도형 복제·손실 없음.
- 배전탑 중첩/전력망 분리/재연결: 전력 이중 계산 없음.
- 기존 공장은 전력 설비를 전부 철거해도 기본 속도 유지.
- 오버클럭 2배를 켰을 때 벨트-가공기 입출력 경계가 깨지지 않음.
- FPS·TPS 및 생산량 계측(오버클럭은 CPU 부하를 늘릴 수 있음).
