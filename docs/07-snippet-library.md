# 07. Factory Snippet Library 기능 사양

## 목적

**[확정] 플레이어가 설계한 우수한 공장 블록을 선택해 보관하고, 언제든 불러와서 다시 배치**할 수 있어야 한다.

기존의 일회성 복사/붙여넣기보다 한 단계 확장된 **영구 라이브러리**다.

## MVP 기능

1. 맵에서 사각형 영역/건물 그룹 선택 → `Save as Snippet`.
2. Snippet 이름, 설명, 태그, 미리보기 이미지(생성 가능하면), 기준 회전 저장.
3. 게임 세이브와 별도 저장소에 영구 보관 → 다른 세이브에서도 접근.
4. 라이브러리 UI: 목록, 검색, 즐겨찾기, 태그별 필터.
5. 선택 시 크기/배치 비용/필요 연구/누락된 건물 모드 표시.
6. 배치 미리보기, 회전 및 반전 후 기존 건물 배치 규칙에 따라 설치.
7. 기존 레벨/연구/건설 비용을 우회하지 않음.

## 이후 버전

- 입력/출력 포트 선언: 예) `Shape A`, `Blue dye`, `Output`.
- 선택한 모듈을 가로·세로·격자 형태로 반복 배치.
- 반복 배치 시 포트에 맞춘 벨트/회로 자동 연결.
- 문자열 코드 및 외부 파일 내보내기/가져오기, 커뮤니티 공유.
- 버전업 시 Snippet 마이그레이션 및 누락된 건물 대체 안내.

위 기능들은 개념 수준에서 우선순위에 따라 나누며, **자동 연결/공유 서버는 MVP 필수 기능이 아니다.**

## 데이터 형식 예시 — 신규 제안 (Shapez 원본 포맷 아님)

```json
{
  "formatVersion": 1,
  "id": "example-snippet-id",
  "name": "8-way balanced splitter",
  "description": "Reusable production module",
  "tags": ["logistics", "balancer"],
  "bounds": { "width": 24, "height": 16 },
  "buildings": [],
  "ports": [],
  "requirements": { "buildingIds": [], "researchIds": [] },
  "metadata": { "sourceGame": "shapez-CE-industrial-reengineering" }
}
```

**독립적으로 직렬화할 데이터:** 건물 타입, 상대 좌표, 회전/반전 상태, 입출력 슬롯 설정, 필터, 회로 연결, 텔레포터 채널, 전력 설정 등. 게임 내부 객체 포인터는 저장하지 않는다.

## 안정성/정합성

- **단일 원점 기준 상대 좌표**를 사용하고, 저장/복원 시 UID 참조를 새로 매핑한다.
- 건물 회전/반전 시 모든 입출력 포트·와이어 핀도 함께 변환.
- 채널형 장치가 다른 모듈의 원격 장치와 무심코 연결되지 않도록 채널 재이름 설정/경고 제공.
- 놓을 수 없는 위치/연구 미해금/비용 부족은 이유를 설명하고 설치를 거부. 불완전한 부분 설치는 명시적 사용자 승인 필요.
- Snippet 저장 중 이동 중인 도형·건물 내부 아이템을 포함할지 정책 결정 필요. **MVP에서는 건물 배치/설정만 보관하고 실제 생산 재고는 복사하지 않는 방향을 추천**한다.
- 가져온 Snippet의 건물 ID가 사라졌을 때 타입을 조용히 제거하지 않는다.

## 테스트

- `save -> close game -> reopen -> load snippet` 구조/설정 동등성.
- 다른 세이브에 넣어도 블루프린트 형태가 유지되는지.
- 반전 + 90/180/270도 회전 조합 검증.
- 모드 건물, 전력선, 회로, 텔레포터 채널 포함 샘플 검증.
- 초대형 모듈 저장/미리보기에서 UI 프레임 드롭이 허용 범위를 넘지 않는지.

## 기존 세이브와의 연결

원본 맵에서 선택한 구역을 새 라이브러리에 등록할 수 있도록 **레거시 건물 매핑 완료 후** 기능을 열어준다. 사용자는 기존 공장의 유용한 구조를 반복 사용하려고 한다. 세이브 전체 이전 성공 여부와 별개로 Snippet 추출에 성공할 수 있는 보조 경로도 장기적으로 검토한다.
