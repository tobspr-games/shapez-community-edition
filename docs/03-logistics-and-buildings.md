# 03. 물류·건물 확장 사양

## 범위

[합의된 방향] 기존 Shapez의 벨트/터널/분배기를 보완하되, 공장의 경로 설계 재미를 없애지 않는 고급 물류를 추가한다.

## A. 1×1 독립 교차로

- 같은 1타일에 **수평과 수직 두 흐름**을 겹쳐 통과시키는 건물.
- 교차하는 도형은 합류/충돌/방향 전환 없이 각자의 방향으로 전진한다.
- 진입 방향과 출구가 지정되어야 하며, 역방향 처리/오버클럭 경계는 테스트로 확인한다.
- **[제안]** 설치 비용을 없애거나 매우 낮게 책정한다. 확정 비용은 미정.
- 테스트: 수평·수직 동시 포화, 한쪽 정체, 게임 저장/복원, 회전/대칭 배치.

## B. 4방향 고급 라우터(Omni Router)

- 북/동/남/서 네 방향에 입력과 출력이 가능하도록 설계한다. 포트의 현재 방향/역할은 명시적으로 관리.
- 계획된 모드: 라운드로빈, 우선순위, 도형 필터, 회로 제어, 수요 기반 배분.
- **중요한 불변조건**: 도형 중복 배출 방지, 정체 시 역류 방지, 막힌 출구에서 무한 반복 처리 금지, 완충/버퍼 정합성 유지.
- 회로 신호는 도형 또는 제어 신호를 전달할 뿐이며 물리적인 전력을 자동 생성하지 않는다.
- 기본 라우터와 고급 라우터의 정확한 설치/유지비는 미정.

## C. 묶음 운송(Bulk / Packet Transport)

- 여러 **동일 도형**을 하나의 논리적 운송 단위 `Packet(shapeId, count)`로 묶는다.
- `Packer -> Bulk transport -> Unpacker`라는 생산 체인을 제안한다.
- 패킷 수량의 보존을 항상 확인한다: 입력 도형 수 = 출력 도형 수 + 내부 보관 수 + 정당하게 소비한 수.
- 기존 일반 벨트와의 인터페이스에서는 `Unpacker`를 거치도록 해 시스템 경계를 명확하게 한다.
- 패킷화가 시뮬레이션 처리량을 줄일 수 있지만, **성능 개선 배율은 실제 벤치마크 전에는 단정하지 않는다.**
- 최대 패킷 수량, 포장 전력, 포장 속도, 패킷 혼합 여부는 미정.

## D. 원거리 아이템 텔레포터

### 기존 모드에서 확인된 기능

- 송신기(`Input teleporter`)와 수신기(`Output Teleporter`)가 **동일한 문자열 채널**을 공유하면 전송된다.
- 기존 소스에서 송신기는 위쪽(top)으로 입력, 수신기는 위쪽(top)으로 출력한다.
- 송신기 보관 슬롯이 비어야 다음 도형을 처리한다.
- 기존 구현은 **출력 엔티티마다 모든 입력 엔티티를 훑는 중첩 반복문**을 사용한다. 약 `O(receivers × senders)` 형태로 증가한다.
- 기존 건물은 Freeplay 관련 보상으로 해금된다.
- 기존 채널은 *문자열 이름*이며, 원래부터 회로 네트워크를 통한 자동 채널 설정을 지원한다는 증거는 없다.

### 확장판 목표

- 고정 문자열 채널 + **회로 제어 채널**을 제공한다. 회로는 채널/활성화 조건을 설정할 수 있으나 실제 도형 데이터 전달은 아이템 시스템에서 수행한다.
- 네트워크 관리자 예시: `Map<channel, {senders, receivers, queuedPackets}>`.
- 전력/처리량/배치 비용을 신형 기술 수준에 맞춰 도입한다.
- 수신기가 꽉 찼을 때 **도형이 사라지지 않아야 한다**. 송신자가 블록되거나 안정적 버퍼에 대기한다.
- 여러 송신기/수신기를 공평하게 처리하는 round-robin 등의 정책을 제공한다.
- 채널 변경, 건물 제거, 저장/불러오기 도중의 인플라이트 아이템 손실 금지.
- 나중에 묶음 패킷 운송까지 확장 가능하게 타입을 설계한다.

### 최소 이벤트 API 예시 (설계 초안)

```ts
type TeleportChannel = string;
interface ItemPacket { shapeId: string; count: number; }
interface TransportResult { accepted: boolean; reason?: 'blocked' | 'no_receiver' | 'no_power'; }
```

인터페이스는 실제 CE 데이터/도형 구현을 확인하고 조정한다.

## E. 이동식 허브 및 중앙 재고

- 기존 Micro Hub의 1×1/2×2 모드를 우선 유지한다.
- 새 허브는 본래 레벨/연구 납품의 동일한 중앙 재고를 참조해야 한다.
- 물류 텔레포터와 허브 납품을 혼동하지 않는다. 허브에 넣은 도형은 진행 시스템에서 소비/집계된다.
- **[제안]** 자동 납품/전력 사용의 고급 허브를 따로 추가할 수 있다. 기본 Micro Hub의 성격을 갑자기 바꾸지 않는다.

## 물류 엔진의 공통 테스트

- N틱 실행 전후 각 도형 수의 보존(정당한 가공/허브 납품/연료 소비 별도 회계).
- 혼합 속도의 일반 벨트와 2배 오버클럭 벨트 경계 처리.
- 건물 복사/회전/반전/Snippet 복원 후 입출력 방향 정확성.
- 브랜치 전후 같은 테스트 맵에서 산출량 및 틱 시간 비교.
