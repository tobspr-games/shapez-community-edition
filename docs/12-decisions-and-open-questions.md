## 이전 제안이지만 **아직 확정되지 않은 수치/행동**

- 발전량 `50 / 200 / 900 / 4,500 / 25,000 / 100,000,000 PU/s`.
- 발전 사이클 `10 / 8 / 6 / 5 / 4 / 2초`.
- 발전기 크기, 연료 입력 버퍼(예: 연료별 20회분), T6의 해금 납품량.
- 오버클럭 비용(벨트 30, 가공기 400 PU/s 등).
- 배전탑 범위(정사각형·반경 2~4), 우선순위 정책, 히스테리시스 시간.
- 텔레포터 전력/설치 도형 비용, 패킷 운송 수량 제한.
- Snippet의 특정 단축키 `Ctrl+Shift+S`, 파일 확장자, 자동 연결 방식.
- 이전 모드 ID를 영구 유지할지, 신규 포맷에서 별도 타입으로 마이그레이션할지.

**Codex는 위 항목을 확정값으로 묵시적 구현해서는 안 된다.** 프로토타입의 상수로 임시 사용할 때는 이름/주석에 임시값임을 표시한다.

## 풀어야 할 질문 — 권장 우선순위

1. 기존 `v1010` 바이너리 포맷 및 CRC 검증을 업스트림으로부터 정확히 재현할 수 있는가?
2. CE가 현재 모드 건물 ID와 스키마를 어느 정도 직접 로드하는가?
3. 공장 이동 중 110,038개 도형을 보존할지, 변환 중 명시적으로 재배치/대기열로 이동하는 방법이 있는가?
4. 범용 mirrored 속성을 도입할 때 내부 공정 입력 순서를 유지할 수 있는가?
5. T1~T6의 **실제 지정 도형 코드**는 무엇이며, 기존 티어 연료의 재사용 비율은?
6. 연료 소비량/전력량의 단위와 경제 균형(제조에 드는 순전력)은?
7. 전력선 전용 레이어를 도입할지, 기존 회로 UI와 어떻게 나란히 표시할지?
8. 전력망 분할·병합·원거리 텔레포터의 배전/과부하 규칙은?
9. 오버클럭이 물류 처리량/건물 내부 버퍼에 주는 변화와 셧다운 복귀는?
10. 기존 모드 원본 코드/이미지/아이콘을 법적으로 직접 가져올 수 있는가?
11. 성능의 진짜 병목은 틱 시뮬레이션·Canvas 드로우·메모리 중 어디인가?
12. C++/Wasm 이식에서 전체 성능이 실제로 개선되는가? 인터페이스 비용은?

## 후속 합의 방법

각 질문에 대해 프로토타입/테스트/사용자 선택 후 `결정 ID`, `날짜`, `상태`, `근거`, `성능 및 세이브 영향`을 기록한다. 사용자 요청보다 이전 AI 제안이 우선하는 일은 없다.
