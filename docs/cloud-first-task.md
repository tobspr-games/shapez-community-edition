# Codex Cloud 첫 작업 프롬프트

아래 내용을 첫 Cloud 작업에 입력한다. 연결할 저장소는
`Ricotta-Cheese/shapez-CE-industrial-reengineering`이며 초기 기준 브랜치는 `master`다.

```text
Repository: Ricotta-Cheese/shapez-CE-industrial-reengineering
Base: shapez Community Edition

먼저 루트 AGENTS.md, docs/README.md, docs/01-project-charter.md부터
docs/13-licenses-and-publication.md까지 모두 읽어라.
[확정], [합의된 방향], [제안], [검증 필요]를 구분하고,
미확정 밸런스 수치를 게임 동작으로 고정하지 마라.

이번 목표는 M0: 개발 환경 검증과 초기 성능 계측 계획 수립이다.
게임 로직, 건물 ID, 저장 형식은 변경하지 마라.
전체 C++ 재작성이나 신규 기능 구현은 이번 작업 범위가 아니다.

1. 현재 커밋 SHA와 실제 체크아웃 상태를 기록하라.
   README, package.json, 잠금 파일, Electron 설정, 빌드 스크립트,
   CI를 읽고 필요한 Node 및 도구 버전을 근거와 함께 정리하라.
2. df -h와 du -sh로 작업 공간을 확인하라.
   설정된 Cloud 환경의 의존성 상태를 확인하고, 실제 저장소에 맞는
   설치 방법을 사용하라. 기존 설정으로 설치됐다면 불필요하게 재설치하지 마라.
3. 존재하는 lint·빌드·테스트 명령을 확인하고 가능한 검사를 실행하라.
   watch/dev 서버만 실행한 것을 빌드 성공으로 간주하지 마라.
   장시간 실행 프로세스는 목적을 달성하면 종료하라.
   실패하면 원인과 선행 조건을 기록하고 관계없는 대규모 수정은 하지 마라.
4. 실제 코드에서 벨트 경로, 아이템 입출력, 가공기, 게임 시간/TPS,
   렌더링, 저장/불러오기, 모드 로더의 주요 파일과 호출 흐름을 조사하라.
5. 초기 성능 기준선 측정을 M0 직후에 진행할 수 있도록 계획하라.
   FPS와 TPS를 구분하고 평균/p95/p99 틱 시간, 메모리,
   동일 게임 시간의 생산량과 아이템 보존을 비교할 방법을 제안하라.
   측정하지 않은 성능 개선을 수치로 주장하지 마라.
6. 개인 원본 세이브와 모드 JS/에셋은 이 저장소에 제공되지 않았다.
   docs/09의 통계는 과거 분석 기준이며 이번에 재현한 결과가 아니다.
   파일 부재로 가능한 코드 조사와 빌드 검증을 중단하지 마라.
   이후 필요한 최소 익명화 테스트 데이터와 로컬 검증 항목을 정리하라.

허용하는 수정은 환경 검증 보고서와 관련 문서의 작은 갱신이다.
환경 설정의 코드 수정이 반드시 필요하면 최소 변경으로 분리하고
이유와 영향을 명확히 설명하라. 기존 검사 실패를 숨기지 마라.
node_modules, 생성 에셋, 패키징 결과, 개인 데이터 및
라이선스 미확인 모드 소스/에셋은 커밋하지 마라.
기본 브랜치로 직접 Push하거나 자동 병합하지 말고 검토 가능한 PR로 제출하라.

결과를 docs/implementation-notes/2026-10-10-m0-environment.md에 기록하라.
보고서에는 실제 실행 명령·결과, 환경 제약, 조사한 코드 경로,
실행하지 못한 검사, 다음 가장 작은 구현 작업을 포함하라.
최종 답변은 한국어로 작성하고 실제 검증과 추정을 구분하라.
```
